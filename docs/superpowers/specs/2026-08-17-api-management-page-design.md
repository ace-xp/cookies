# 外部服务管理页设计

> 2026-08-17 · 把散在 `.env`、数据库和两个设置页里的外部服务配置，收进一张可看可改的表

---

## 一、要解决的问题

平台目前依赖一批外部服务，页面上按 **14 条可管条目**登记（模型部分按**能力**登记，因为同一个上游连接可能被多条能力共用，而用户关心的是「哪个功能会受影响」）。它们的配置分散在三个地方：

- `.env`：80+ 个环境变量（见 `.env.example`）
- 数据库：`provider_connections` / `provider_credentials` / `provider_model_routes`、`insight_miyun_connections`
- 界面：只有「系统设置」页里的视频模型和密云连接两块（`src/components/ModelSettingsPage.tsx`）

由此产生两个具体的痛：

1. **看不清**：没有任何一处能回答「平台现在依赖哪些外部服务、哪些配了、哪些通、哪个断了会影响什么功能」。
2. **改不动**：绝大多数配置只能登服务器改文件再重启后端。

本设计解决这两个问题，且不打断现有部署。

## 二、范围

| 决定 | 结论 |
| --- | --- |
| 管什么 | 平台**调用的外部服务**（模型、素材源、存储、转档等），不含平台自己对外的 493 条接口 |
| 放哪 | **扩现有 `/settings`「系统设置」页**，不新开入口 |
| 能改到什么程度 | 第一档服务页面可编辑，第二、三档只读展示状态与改法 |
| 保存后 | **不重启后端即生效** |
| 现有 `.env` | 不动、不迁移、不失效；数据库优先，`.env` 兜底 |

明确不做：

- 不管理平台自己暴露的 HTTP 接口（那是另一件事，另立项）
- 不在页面上暴露数据库连接、管理员账号、加密主密钥
- 不做多租户/多组织的配置隔离（当前部署为单组织，沿用 `organization_scope = '*'`）
- 不做配置变更的审批流（有版本和回滚即可）

## 三、服务目录（14 条，分三档）

### 第一档：页面可编辑（9 条）

这一档里，**前 7 条已经从 `provider_model_routes` 读配置**（`internal/platform/provider/gateway_config.go:324-359`），底座具备热生效能力，缺的只是界面。

| 服务 | 能力编码 | 现在配在哪 | 断了影响什么 |
| --- | --- | --- | --- |
| 文本模型 | `text.generate` | 数据库路由（`adapter_gateway` / `ark`） | 策略生成、文案撰写、创意脚本 |
| 图片模型 | `image.generate` | 数据库路由（`adapter_gateway`） | 图片生成、图文创意 |
| 视频模型 | `video.generate` | 数据库路由（已有界面） | 视频创作出片 |
| 图片理解 | `vision.understand` | 数据库路由（`adapter_gateway`） | 素材理解、内容分析 |
| 语音合成 | `speech.synthesize` | 数据库路由（`minimax_speech`） | 视频配音 |
| 文档视觉解析 | `document.vision.parse` | 数据库路由（`las_operator`） | PDF/文档类素材解析 |
| 联网研究 | `research.web` | 数据库路由（`ark`） | 需求分析的联网取证 |
| 密云素材源（即 YouShu 有数） | — | 端点在 `COOKIES_MIYUN_*`，会话凭据在 `insight_miyun_connections`（已有界面） | 素材采集与竞品洞察全链路 |
| 火山语音 | — | 纯 `.env`（`COOKIES_VOLCENGINE_SPEECH_*`），**后端启动时装配** | 视频配音（volcengine 路线） |

**注**：密云与 YouShu 有数是同一条上游。`COOKIES_MIYUN_ENDPOINT` 默认值即 `https://api.youshu.youcloud.com/graphql`，采集走 `internal/integrations/crawler` 的 YouShu 客户端。目录中按一个服务登记，避免界面上出现两条看起来独立、实则同源的记录。

### 第二档：只读展示（5 条）

页面显示「配没配、通不通、断了影响什么、要改动哪个环境变量、改完需重启」，但不提供编辑。

| 服务 | 环境变量 | 断了影响什么 |
| --- | --- | --- |
| TOS 对象存储 | `COOKIES_TOS_*` | 素材上传与全部文件读写 |
| Gotenberg 转档 | `COOKIES_DOCUMENT_CONVERTER_BASE_URL` | PPT/Word 转 PDF，方案导出 |
| 抖音商品源 | **无配置项**，只展示可达性 | 从商品链接带出商品信息 |
| ClamAV 病毒扫描 | `COOKIES_SCANNER_MODE` / `COOKIES_CLAMAV_ADDRESS` | 上传素材的安全扫描 |
| FFmpeg / FFprobe | `COOKIES_FFMPEG_PATH` / `COOKIES_FFPROBE_PATH` | 视频转码、时长与规格识别 |

### 第三档：不进目录、不上页面

数据库连接、管理员账号、`COOKIES_PROVIDER_MASTER_KEY` 与 `COOKIES_MIYUN_MASTER_KEY`。改错会导致整站不可用或全部已存密钥无法解密，只能由部署方在服务器上处理。

这一档**不写进服务目录**，页面不显示、不提示、不留入口。因此目录声明的档位只有 `editable` 和 `readonly` 两种。

## 四、后端设计

### 4.1 外部服务目录（新增）

在 Go 代码里声明一份服务目录，**不进数据库**——它描述的是「平台依赖了什么」，属于代码事实，随代码版本走。

每条声明包含六项：

```
服务编码        catalog code，如 "model.text"、"miyun"
中文名          界面展示用
档位            editable / readonly
影响面          断了会影响哪些功能，一句人话
配置字段        字段名、类型、是否必填、是否密钥、说明
探针            如何验证这条配置真的能用
```

页面完全由这份目录渲染。新增第 13 个外部服务时，只加一条声明，前端代码不动。

这份目录同时是**唯一的权威清单**——回答「平台到底依赖了什么」不再需要翻 900 行的 `internal/platform/config/config.go`。

### 4.2 存储：复用现成三张表

`provider_connections` / `provider_connection_revisions` / `provider_credentials` 已经提供密钥加密存储、版本号、修订历史与回滚。当前 `connection_type` 被 CHECK 约束限定为 `adapter_gateway`，需要一次迁移放开，让第一档服务共用。

**不新建凭据表。** 密云沿用已有的 `insight_miyun_connections`（它有自己的会话语义和错误码字段），由目录声明指向该存储，界面形态与其他服务一致。

### 4.3 保存即生效

七条模型能力已经通过 `resolveRoute` 在调用时读数据库，天然热生效。需要处理的只有两处：

1. **火山语音**：从「启动时由 `.env` 装配」改为走 `speech.synthesize` 路由，与 MiniMax 同构。
2. **本地自管的 ark_image / ark_text 分支**（`cmd/cookies-api/main.go:966,996`）：这两条只在 local 环境生效，改为同样从路由解析，消除「同一能力两套配置来源」。

同时把 `internal/platform/provider/gateway_config_write.go` 里写死单个视频连接的逻辑（`VideoConnectionID` 等常量）一般化为按目录编码读写，**收编后不保留两套写入路径**。

配置服务带内存缓存，写入时主动失效，避免每次调用都打库。

### 4.4 配置读取优先级

```
数据库有记录        → 用数据库的值，界面标「已在页面配置」
数据库无记录        → 回落 .env，界面标「当前值来自部署配置」
两处都没有          → 标「未配置」，并列出该服务影响的功能
```

现有部署不需要做任何迁移动作即可升级。

### 4.5 接口

沿用现有 `platform/v1/provider/*` 前缀与鉴权口径：

| 方法与路径 | 用途 | 权限 |
| --- | --- | --- |
| `GET /platform/v1/provider/services` | 读取整份目录与各服务当前状态 | 登录 |
| `PUT /platform/v1/provider/services/{code}` | 保存某个服务的配置 | `provider.configuration.write` |
| `POST /platform/v1/provider/services/{code}/verification` | 只探测不保存 | `provider.configuration.write` |

现有 `GET/PUT/POST /platform/v1/provider/video-configuration` 三条接口在新接口上线后作为兼容层保留一个版本，前端切换完成后移除。

### 4.6 安全

- 密钥只进不出：响应体只含末四位掩码，完整密钥不出服务端
- 写操作要求 `provider.configuration.write`（现成 scope）
- 保存前强制探测，探不通不落库
- 主密钥不经页面，也不显示
- 配置变更写审计记录（谁、什么时候、改了哪个服务、版本号），不记录密钥内容

## 五、前端设计

界面从简，重点在功能。单页，两部分：

**服务清单表**——每行：服务名 / 状态 / 影响面 / 最近检查时间与结果。状态四态：`可用`、`已配置但连不通`、`未配置`、`已关闭`。

**编辑区**——点第一档某行展开，按目录声明动态渲染字段，三个动作：`测试连接`、`保存`（保存前自动探测）、`刷新状态`。第二、三档展开后只显示「这项要改哪个环境变量、改完需重启」。

现有 `ModelSettingsPage.tsx` 里的视频模型表单和 `MiyunConnectionSettings.tsx` 并入统一形态，不保留两种交互。

## 六、错误处理

### 6.1 探测结果分四类，每类给下一步动作

| 结果 | 界面说法 |
| --- | --- |
| 连得通 | 已连通，可以用 |
| 认证失败 | 密钥无效或已过期 → 去服务商后台重新签发 |
| 地址或网络不通 | 地址填错，或服务器出不了网 → 检查地址、检查服务器网络 |
| 服务端拒绝 | **原样带上对方的说明文字**，不做二次猜测 |

第四类有明确教训：密云曾只保留错误码 `00:403001`，界面猜成「请重新复制 Cookie」，实际是「套餐版本不够」，导致反复重贴 Cookie 白折腾（见 `migrations/insights/20260814100000_insight_miyun_connection_error_message.up.sql` 的注释）。上游给了人话说明就必须原样透出。

### 6.2 页面降级

- 后端不可用 → 显示「读取失败，重试」，**不得渲染成「全部未配置」**
- 单服务探测超时 → 该行标「检查超时」，不影响其余行
- 保存时版本冲突 → 提示「配置已被更新，请刷新后重试」，不覆盖对方的修改

## 七、验收标准

- 每个探针有单元测试，覆盖连通 / 认证失败 / 超时 / 服务端拒绝四种上游回应
- 集成测试：改配置 → 立即发起一次真实调用 → 断言走的是新配置（不重启进程）
- 回落测试：数据库无记录时仍读到 `.env` 的值，且界面标注来源为部署配置
- 掩码测试：任何响应体都不含完整密钥
- 目录完整性测试：`config.go` 中每个**指向外部服务**的环境变量，要么能在服务目录中找到归属，要么落在一份显式的豁免清单里（数据库、管理员账号、主密钥、本地路径等第三档项目）。新增一个外部依赖却忘了登记时，这条测试会红
- 8091 环境实跑：改一个模型密钥 → 保存 → 直接去创意模块出图 → 确认生效，且全程未重启后端

## 八、已知风险

| 风险 | 说明 |
| --- | --- |
| 放开 `connection_type` 约束 | 需要迁移，且要确认现有视频连接数据不受影响 |
| 收编视频配置的写死逻辑 | `scripts/configure-ark-video.ps1` 与 `gateway_config_write.go` 共用同一组常量 ID，一般化时要保证脚本仍能覆盖同一条记录，不产生重复连接 |
| 探针会真实调用上游 | 部分服务的探测调用可能计费。探针一律选用最轻的只读操作，并对探测频率做节流 |
| 火山语音改走路由 | 属于修改现有调用链路，需要单独验证配音功能不回归 |
