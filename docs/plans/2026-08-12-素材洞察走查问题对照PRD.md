## 第一类：实现违背了 PRD 明确写下的要求（9 条）

这一类是真的要修。

### V. 权限三档不可分 —— 冲突最明确，涉及面最广

| 出处 | 原文 |
|---|---|
| 03 §导航规则 | 权限使用 `insights.*` 动作，**数据口径、经验确认和普通查看分别授权** |
| 03 §11.2 | 策略/创意人员可以提出洞察反馈，但**确认组织经验需指定角色** |
| 03 §11.2 | 数据分析人员可配置 Cohort 和指标口径，**普通成员不能修改原始事实** |
| 22 §6.2 | 能力运营：**仅分析运营角色可见** |
| 22 §6.2 | 系统设置：**仅管理员可见** |

实现：owner / admin / member 三种角色**一次性拿全** `insights.read` + `insights.write` + `insights.confirm`，只有 auditor 是纯只读。三个权限根本分不开，"确认需指定角色"无从谈起。

而合并后的「设置」入口（吃掉了 PRD 的数据质量 + 能力运营 + 系统设置）**没有任何角色门**，所有人都能进、都能改判定阈值。

另外，「确认权限」那一屏写「只能按账号授予，不能按角色配」——和代码正好说反了：权限只按组织角色发，根本没有按账号授予的通道。

> 附带一条反向冲突：03 §11.2 说「数据分析人员可配置指标口径」，而实现的指标字典页明确写「不能在界面上改，改口径要改代码、走评审」。这个偏离是有正当理由的（PRD §14 要求"支持重算、不静默改写历史报告"），但它确实推翻了 §11.2，应该在 PRD 里改掉而不是留着。

### M. 提取失败在界面上完全隐身

| 出处 | 原文 |
|---|---|
| 15 §2 页面状态 | 每个列表、详情、编辑器、**长任务**页面必须设计：排队、运行、等待用户/审批、部分完成、**失败**、取消和结果未知 |
| 15 §3 状态转换矩阵 | 每个业务实体必须补充：当前状态、动作、前置条件、权限、目标状态、**失败状态**、是否可撤销 |
| 03 §13 埋点 | 分析任务成功率、P95 时长和数据新鲜度 |

实现里提取失败只写进运行记录，素材状态原地不动，三个队列一个都不收它。

**顺带暴露 PRD 自身的一个缺口**：03 §11.1 的状态机 `待数据 → 待匹配 → 可分析 → 分析中 → 待确认 → 已确认/待复审/已失效` **没有失败分支**。实现"填空"的方式是让它退回「可分析」，于是失败就看不见了。这一格 PRD 得先补上。

### Q / P. 素材和外部证据都没有"引用"这一格

| 出处 | 原文 |
|---|---|
| 03 AM-001（P0） | 接收创意模块产物、**上传文件或外部引用**，建立稳定素材与版本 ID |
| 03 §4 末 | 素材可以只保存外部文件引用，但**必须保留稳定标识、创意版本和平台对象关系，确保效果数据能正确归属** |
| 03 §14 | 素材二进制和预览统一使用媒体资产平台的 Asset ID/Version |
| 03 §17.5 待确认 | 本稿允许只保存**受控引用**与分析所需预览 |
| 15 §2 | 错误信息包含发生了什么、保留了什么、**用户可以做什么** |

实现：
- 「登记素材」表单没有上传口、没有外部引用口、没有补录平台对象引用的地方 → 直接违反 AM-001 和 §4 末。
- 「外部素材」表单同样没有文件也没有链接 → 收进来的是一条什么都不指向的记录。
- 「量一下」的错误提示告诉人「从创意导入的才带这个引用」，而这条路对已登记的素材不存在 → 违反 15 §2 的「用户可以做什么」。

PRD §17 待确认第 5 条允许不存原文件，但**没有允许连引用一起不存**——"受控引用"里那个引用是必须项。

### O. 数据新鲜度没有起到 PRD 要它起的作用

| 出处 | 原文 |
|---|---|
| 03 §10.3 防误读 | 样本不足、窗口过短或**归因延迟时显著提示** |
| 03 AM-002（P0） | 数据导入…**展示口径和新鲜度** |
| 10 §验收 4 | **未匹配、延迟或异常数据不会产生强洞察或自动优化动作** |
| 10 | 数据窗口未成熟、追踪异常或**延迟超阈值时，阻止确定性优化建议** |
| 15 §9 | 图表必须先保证…**数据新鲜度**和置信信息清晰 |

实现：唯一那条数据源状态是「未启用」，而新鲜度检查**整个跳过非启用的数据源**。于是它的数据照样撑起分析页、投前、指标字典的每一个数字，却不受任何新鲜度闸门约束。

同一屏还直接自相矛盾：空态写「所有启用中的数据源都在按时回数，没有滞后」，紧挨着下一行是「抖音 · 正常 · 滞后 2 天」。

### N. 「版本」列对应的不是 PRD 要求的那个版本

03 AM-003（P0）：**将平台创意/广告 ID 与 cookies 素材版本对应**。
03 §4 末：必须保留稳定标识、**创意版本**和平台对象关系。

实现那一列打的是映射记录自己的修改次数，不是素材版本。表标题「到底是我们哪个素材版本」问的正是 PRD 那件事，答的是另一件事。

### I. 「管经验」不显示缺哪几项

| 出处 | 原文 |
|---|---|
| 22 §6.2 经验库 | 建立 Experience 详情路由；**确认结论、条件、反例、证据、复审日期和引用记录** |
| 03 §15 验收 9 | 洞察卡包含结论、样本、适用条件、证据、风险和下一步建议 |

「管经验」就是 doc22 指定的那个页面，而"缺哪几项"只在投前渲染。能动手补的人看不见要补什么，按钮上还统一写「补齐依据」。

### J. 经验说不清自己按哪一版标准判的

| 出处 | 原文 |
|---|---|
| 03 §15 验收 12 | **任一分析结论**能回溯到素材、数据截止时间、指标和 Skill 版本 |
| 03 §14 | 任何分析都能追溯到素材版本、数据快照、**方法**和 Skill/算法版本 |
| 15 §7 AI 披露 | 展示来源、**版本**、适用范围、置信提示、模型/Skill 血缘和最后更新时间 |

「按第 N 版阈值判定」这个印，分析页盖了、复盘盖了，**唯独经验没有**——接口没这个字段，数据库没这一列。经验恰恰是这个模块最终交付、也是下一轮唯一会被引用的东西。

（严格说"判定阈值版本"是 8-11 重构新增的概念，PRD 原文说的是"指标和 Skill 版本"。但验收 12 的要求是"任一分析结论可回溯到判定所依据的东西"，阈值现在就是判定所依据的东西。）

### D. 模式归纳绕开了受控词表

03 §5 末：**受控词表由管理员维护，避免同义词碎片化。**

「反复有效的内容特征」是按自由文本原样分桶的，同一个意思写成两种说法就是两个桶。这正是 §5 末那句话要防的事，而系统里明明有词表机制（设置 → 变量字典），这条路不走它。

### L. 「可分析」这个词在同一屏指两个不同的集合

03 §11.1 把「可分析」定义为状态机上的一个具体状态。而素材总览的「可分析素材 5 条」是三个状态之和，同屏下面的队列又按真正的「可分析」来数。PRD 定义的状态名被当成了口语词用。

## 第二类：PRD 已被 8-04 / 8-11 重构有意推翻，但一直没同步（清单里 W、X 的根因）

这一类不是"实现错了"，是**两套词汇、两套导航同时活在代码里**。

### 导航：PRD 11 个一级入口 vs 现在 7 个

03 §一级导航表 + §15 验收 13 定义了 11 个入口。现状：

| PRD 的入口 | 现在在哪 |
|---|---|
| 投前洞察（策略证据/创意建议/历史模式/风险与反例/引用记录） | 「投前」，5 个视图并成 2 个 |
| 投后分析 `/insight/performance` | 「分析」`/insight/analysis` |
| 数据接入 `/insight/data-sources` | 「素材 → 数据接入」 |
| 分析素材库 `/insight/assets`（全部素材/待匹配/待提取/特征库/版本关系） | 并进「素材」 |
| 内容分析 `/insight/content`（七个视图） | 并进「素材 → 变量」 |
| 实验中心（一级导航） | 路由保留但侧栏 `hidden` |
| 经验库 `/insight/experiences`（五个状态视图） | 「经验」（查/管两个视图） |
| 报告中心 `/insight/reports`（任务复盘/周期报告/自定义报告/导出记录） | 「复盘」，后三个**没有** |
| 数据质量 + 能力运营 + 系统设置 | 三合一成「设置」 |
| 系统设置的「**通知**」和「**报告模板**」 | **完全没有** |
| —— | 「米云素材」（PRD 里没有，上游同步来的） |

路由也几乎全不一致。这些偏离都有明确理由（写在 `navigation.ts` 的注释里，也在基线文档 §5 登记过），**但 PRD 一个字都没改**。

**X 那四处"指向不存在的入口"的文案，写的是「分析素材库 · 特征库 / 待提取 / 待匹配」——一字不差就是 PRD §一级导航表里那一行。**所以那不是笔误，是 PRD 版导航的残留。

### 词汇：名词表禁掉的词，多数是 PRD 的原话

| 名词表判为废词 | PRD 原文出处 |
|---|---|
| 方向性结论 / 方向性观察 | 03 §7.3「变量混杂或样本不足时只给**方向性观察**」；§8.1 置信提示「充分、**方向性**、样本不足、存在混杂」 |
| 存在混杂结论 | 03 §8.1 同上 |
| 样本不足 | 03 §8.1 同上 |
| 强结论 | 03 §10.3「数据异常时暂停生成**强结论**」；10 §验收 4「不会产生**强洞察**」 |
| 高置信 / 低置信 | 03 §5 末「自动特征必须标识为 AI 提取并保存**置信级别**」 |

而且**档位数量就不一样**：PRD §8.1 是四档（充分 / 方向性 / 样本不足 / 存在混杂），实现是三档（✅ 能归因 / 👁 只是观察 / ❓ 算不出来）。

所以清单里 W 那条"废词还散落在文案里"，本质是：**这些文案是照 PRD 写的，重构改了词表却没改 PRD，也没有任何测试覆盖前端文案**（那个"有测试拦着"的测试只查后端 12 个枚举名）。

> 一句话：不先决定"PRD 跟着实现改"还是"实现跟着 PRD 改"，W 和 X 修一次还会长回来。

## 第三类：PRD 没要求、实现自己加的强制（2 条）

### F. 提交复盘必须先挂一次投放执行

- 03 AM-015（P0）：按任务汇总素材表现、实验结论、经验和下一轮建议 —— 没有这个前置。
- 22 §6.4 验收 5：投后分析**可以创建当前 Project 的复盘报告** —— 也没有。

这是实现自加的门槛。不一定错（复盘本来就该对应一轮真实投放），但它挡住了 22 §6.4 验收 5、6、7、8 那条链在没有投放数据时的走通，属于需要你拍板的产品决定。

### G. 复盘提交后不可改

15 §3 通用原则：「已确认/批准版本不可编辑；**修改创建新草稿**。」

不可编辑是对的，但 PRD 配套要求的"修改可以创建新草稿"这一半，我没在界面上找到入口（未逐项验证，列为待核）。加上复盘全流程压根没有填摘要的地方，一旦提交，这一轮就永远是「（这一轮还没写摘要）」。

## 第四类：PRD 没覆盖，属实现内部的自相矛盾（其余各条）

这些跟 PRD 不冲突，是实现自己跟自己打架，改起来风险最低：

- **A**（分析页徽章显示六屏合并档位）——PRD 只在 §10.3 要求"显著提示"，没规定徽章粒度；但代码注释自己写明了不该这么干。
- **C**（「反复有效」都是 1 条）——PRD §7.5 没规定次数门槛，§16 风险表倒是支持加一个。属 PRD 缺口 + 文案自我承诺落空。
- **E**（复盘档位是快照、没说自己是快照）——冻结快照**符合** 03 §14「不静默改写历史报告」，缺的只是 15 §2 要求的"数据过期"披露。
- **H**（投前和查经验返回同一批数据）——与 22 §6.4 验收 4「每个可见分析标签都必须改变数据集或分析主视图」精神相悖。
- **U**（数值字段被报成"词表未发布"）——03 §5 末只说"受控词表"，没区分字段类型；后端自己分清了，前端没跟上。
- **K**（占位文字「尚未关联产品」被当筛选条件）、**R**（空态用错术语）、**S**（空态说两遍）、**T**（已失效素材两处待遇不一致）、**G-2**（打完整原始 ID）——纯实现瑕疵。
- **B**（「算不出来」也能记一笔）——PRD 未禁止，待验证。

## 建议的处理顺序

1. **先拍板第二类**：PRD 是跟着实现改，还是实现回退到 PRD？这一条不定，W、X 以及未来所有文案问题都会反复。我的建议是 PRD 跟着实现改——重构的理由都写在代码注释里且成立，而 PRD 还停留在 v0.7/v0.8 草案。
2. **再修第一类里的 V（权限）和 M（失败隐身）**：一个是治理漏洞（所有人都能改判定阈值、都能确认结论），一个是会让人看着错数据下判断。
3. **然后 Q / P / N / O**：都是"数据归不归得上素材"这条主链上的，PRD 把它们全标了 P0。
4. **第四类最后**：便宜、低风险，可以顺手带。

## 处理结论（2026-08-13 补记，修复与复验完成后回填）

### 第二类怎么办：**PRD 跟着实现改，等五期做完一次性同步**

拍板结论按上面第 1 条建议走，理由不变：重构（8-04 / 8-11）的每一处偏离都在
`navigation.ts`、`vocabulary` 相关模块的注释里写明了理由且成立，而 PRD 停留在 v0.7/v0.8 草案。

**但不逐条改 PRD**：现在 P0~P5 六份计划刚落地，导航、词表、状态口径还在收口，
这时候同步一次 PRD，下一次改动又要再同步一次。改为**五期全部做完后一次性回写**，
在此之前以实现为准、以基线文档
（`docs/plans/…素材洞察功能基线文档`）登记偏离。

为了让「W、X 修一次还会长回来」这句话不成立，本轮补了两道护栏，不依赖 PRD 同步：

- 前端文案纳入测试：废词与失效入口的检查从"只查后端 12 个枚举名"扩到页面文案；
- 权限、失败原因、角色三处措辞各自收敛到单一出处
  （`data/scopes.ts` 的 `roleSentence` / `insightScopeSummary`、`readableError` /
  `isModelSetupFailure` / `modelSetupHint`、API 层的 `permissionMessage`），
  措辞只在一个地方写，抄不出第二份。

### 更正：第三类 G 那条"未逐项验证"的判断，核完是**错的**

原文写「PRD 配套要求的『修改可以创建新草稿』这一半，我没在界面上找到入口（未逐项验证，
列为待核）」。核过了，**入口一直在**——分析页的「记一笔」本身就是开下一份草稿的动作。
真正的问题不是没入口，是那条路上有一个死锁：

`insight_reports` 的唯一键 `(organization_id, project_id, execution_id, window_start, window_end)`
把**已确认的报告**也算进了"同一个窗口只能有一份草稿"里。于是提交复盘时没选投放执行
（执行本来就是选填），这份已确认报告占着 `execution_id = ''` 的位置；隔两天在同一窗口再按
「记一笔」，建草稿撞键，重试三次三次都撞，最后报「有人同时改了，请刷新重试」——刷新多少次
都没用，这个窗口从此再也记不了一笔。

已由迁移 `migrations/insights/20260813100000_insight_report_draft_slot_key` 修好：给唯一键加一列
生成列 `draft_slot`（草稿是 1，已确认是 NULL），MySQL 唯一键不约束含 NULL 的行，于是同一
(项目 + 执行 + 窗口) 下可以躺任意多份已确认的历史报告，同时只允许一份未提交的草稿——
这正是这个键原本想表达的意思。已端到端验证：提交复盘 → 同窗口再记一笔 → 开出新草稿，
老那份定格留档，符合 15 §3「已确认版本不可编辑，修改创建新草稿」。

（G 的另一半"复盘全流程没有填摘要的地方"是真的，已在第 16 项修复里补上。）

### 其余各类的落点

- **第一类 9 条**（V / M / Q / P / O / N / I / J / D / L）全部按 PRD 原文修实现，没有反过来改 PRD。
  其中 V 附带的反向冲突（§11.2「数据分析人员可配置指标口径」）维持实现口径不变——
