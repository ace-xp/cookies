## 一、屏幕上的数字和结论互相打架

这一类最要紧：人看了会照着做，而它是错的。

### A. 分析页顶上的徽章说的不是这一屏的话

六个视图共用一个徽章，它显示的是**六屏合起来的最弱一档**。所以在「指标总览」上，徽章写着 ❓算不出来、还配一句「这一屏里有结论连差异存不存在都判断不了」，而正文里每一条都是 ✅ 能归因。趋势、疲劳两屏同样如此。

代码自己在注释里已经写明这样做不对（`src/components/insight/analysis/AnalysisPage.tsx:153`，注释在 184–187 行）。

### L. 「可分析素材 5 条」和「可分析」是两个意思

素材总览上的这个 5，是三种状态加起来的：真正「可分析」的 1 条 + 「待确认」的 4 条。而唯一那条真正「可分析」的素材，同时又被列进下面「待提取变量 1」的队列里——那个队列自己的说明是「类型已识别、还没提变量」。

同一条素材，在同一屏上既叫「可分析」，又叫「还没提变量」。

外部证据那 2 条既不进这个 5，也不进任何一个队列，屏幕上没有一句话说它们算在哪。

### M. 提取失败的素材，哪个队列都不进

「路演品牌片（客观量验证）」最近一次提取是**失败**的（原因：还没有配置可用的文本模型），35 个变量里空着 33 个。但：

- 它的状态还是「可分析」
- 它被计进了「可分析素材 5 条」
- 「提取出了问题 0」这个队列不数它——那个队列只数「提取成功但结果存疑」的

成因：提取失败时只写失败记录，不动素材状态（`internal/systems/insights/extraction.go:358`）。结果就是**真失败的素材在界面上完全隐身**。

### E. 复盘里的档位和分析页对不上，而且没说自己是快照

同一条发现，复盘草稿里是 👁 只是观察，今天回分析页看同一个窗口是 ✅ 能归因。原因是档位在「记一笔」那一刻就冻住了，之后不再重算——这个设计本身可以接受，但屏幕上一个字都没说它是快照，人会以为两边有一边算错了。

### O. 唯一的数据源是「未启用」，可它的数据是所有数字的来源

数据接入里那条抖音数据源状态是「未启用」，18 行数据已入库，分析页、指标字典、投前的每一个数字都来自它。屏幕上没有任何一句话解释「未启用」到底禁掉了什么。

**同一屏上直接自相矛盾**：设置 → 数据体检 → 新鲜度，空态写「所有启用中的数据源都在按时回数，没有滞后」，紧挨着下面一行就是「抖音 · 主账户 · **正常** · 数据到 2026/8/10 · **滞后 2 天**」。而这个「正常」和数据接入页的「未启用」还是两个不同的字段，界面上都叫「状态」。

## 二、说了做不到的话

### C. 「反复有效」名不副实

投前 → 结论写「另有 4 个反复有效的内容特征」，历史模式整屏标题是「哪些内容特征反复有效」、导语说「比只被提过一次可信得多」——可这 4 个，每一个都写着「1 条结论提到」。后端没有设任何次数门槛。

### D. 这些特征是按自由文本分桶的，不查字典

同一个意思写成两种说法，就变成两个「1 条」的桶，永远攒不到「反复」。手工敲进去的字典键会直接以英文原样显示在页面上。

### I. 「修订，补齐依据」名不副实，而且缺什么只有看不见的人看得到

按钮上写「补齐依据」，但它不看这条经验到底缺不缺——依据齐全的卡上也是这行字。真正的「缺哪几项」只在投前那一屏渲染，管经验一个字都不显示。**能动手改的人，看不到要改什么。**

同一张卡上，「什么情况下不成立」这一格没人填的时候，写的是「还没人试过推翻它」——把「没人填」说成了「试过了没推翻」。

### W. 名词表说「有测试拦着」，但测试一行页面文案都没查

设置 → 变量字典 → 名词表，整屏的立论是「表上『不要再叫』的说法不许再出现在任何页面文案里，有测试拦着」。

实际那个测试只检查后端 12 个枚举的中文名，前端一个文件都不看（`internal/systems/insights/glossary_test.go`）。废词就在现场：

| 废词 | 出现在哪 |
|---|---|
| 低置信 | **同一个入口隔壁 tab**：设置 → 变量字典 → 分析 Skills，「低置信提取值得单独看」 |
| 强结论 | 分析 → 驱动因素的导语「不给强结论」；数据体检的阻断提示；数据接入的数据源告警 |
| 沉淀 | 复盘的**视图名就叫「已沉淀经验」**；导航介绍语、经验查不到时的提示都在用 |

### V. 确认权限那一屏，说反了

屏幕写「目前只能按账号授予，不能按角色配」。代码里正好相反：权限**只**按组织角色发（`internal/platform/identity/mysql_store.go:19`），根本没有按账号授予的通道。

更关键的是这一屏的立论——「分开授予的意义在于：提特征的人和认结论的人可以不是同一个人」——在当前实现下做不到：owner / admin / member 三种角色**全都同时拿到读、写、确认三个权限**，只有「审计员」是纯只读。「建议授予：对结论负责的人，人数宜少」这句话没有任何办法执行。

（权限相关，改动前建议单独确认。）

### P. 外部证据收的是一条既没有文件、也没有变量的登记

「外部素材」的登记表单只有标题、来源说明、用途、补充说明、素材类型——**没有任何上传文件或填链接的地方**，也没有填变量的地方。可整屏文案在讲「原片将在 X 前后清掉，只留下人标过的变量」「原件已删，只剩标注的变量」。这两样东西一样都不存在。后端还照样给它分配了一个存储路径。

### Q. 手工登记的素材永远量不出客观变量，而错误提示叫人「先补上」

「量一下」这个动作要求素材指向素材库里的真实文件，只有「从创意导入」这条路会写上这个指向。而「登记素材」表单里没有这一格，整个模块也没有任何补录的地方。

屏幕实测：「夏季前贴·C版（登记验收）」的「量一下」按钮是灰的，提示写「从创意导入的才带这个引用」——等于告诉人「你现在做不到，去做另一件你现在也做不到的事」。

## 三、写进去的东西丢了 / 补不回来

### G. 复盘永远没有摘要，且提交后再也补不上

从建草稿到提交，全流程没有一个填摘要的地方，后端也不写。所以复盘列表主列 5 行全是「（这一轮还没写摘要）」，只能靠时间戳分辨。而复盘一旦提交就「不能再改」。

### J. 经验卡的「凭什么」没盖阈值印，是端到端缺的

结论用的是哪一版判定阈值——分析页、复盘都盖了印，唯独**经验**没有。不是前端漏渲染：接口返回的 4 条经验都没有这个字段，数据库表里根本没有这一列。

经验是这个模块最终要交付的东西，也是下一轮开工时唯一会被引用的东西。它恰恰是唯一说不清自己按哪一版标准判的。

### F. 提交复盘必须先挂一次投放执行

提交面板强制要选一条投放执行记录，且下拉里没有「不选」这一项。没跑过投放就复盘不了。

### B（待确认）. 「算不出来」的结论也能被记一笔

趋势、疲劳两屏里判为 ❓算不出来的行，「记一笔」按钮照样可点，也就是说一条「判断不了」的结论能被钉进复盘。素材对比那一屏是拦住了的。——这条我只在界面上观察到，没有实际点下去验证，因为会污染演示数据。

## 四、名字和指路是错的

### X. 好几处提示把人指向一个已经不存在的入口

「分析素材库」这个入口在 8-11 那次重构里已经并进了「素材」，但文案里还在指它：

| 位置 | 文案 |
|---|---|
| 分析 → 驱动因素空态 | 去「分析素材库 · 特征库」补齐特征 |
| 分析页提示 | 去「分析素材库 · 待提取」补 |
| 分析 → 总览 | 去「分析素材库 · 待匹配」认领 |
| 数据接入 → 详情 | 认领在「分析素材库 · 待匹配」里做 |

最后一条尤其绕：那个面板本身就在「数据接入」里，它让人去别处做一件当场就能做的事。

### N. 素材映射的「版本」列打的不是素材版本

表标题就叫「平台上的这条广告，到底是我们哪个素材版本」，可那一列 4 行全是 `v2`——它打的是这条**映射记录自己**的修改次数，不是素材版本。下拉里每条素材都写着「第 1 版」。

同一屏上「归属」列只给一截 id（「已归到素材 0cb88321」），而组件里明明有素材名；点开详情又换成完整的原始 id。

### R. 「平台素材号」的空态用错了词

写的是「还没和平台上的对象对上号」——但「平台对象」是素材映射那边的词。人照这句话跑去数据接入，会发现对象早就匹配好了，可文件还是没有。它缺的其实是素材库里的媒体文件。

### G-2 / 复盘详情打完整原始执行 ID

「执行 deliveryexecution_dbaf26fe7d1e5b4a1d632cb42e682918 ·user_local 于 …」——下拉里用的是短 id，这里是完整原始串，而且「·」和「user_local」之间少一个空格。

### K. 「查经验」把占位文字当筛选条件用

没关联产品的项目，查经验会拿字面串「尚未关联产品」去匹配产品名。后端早就知道要排除这个值。

### H. 「投前」和「经验 · 查经验」返回的是同一批数据

两个侧栏入口，返回完全相同的两条经验。分工是有设计理由的（一个是决定、一个是翻账），但屏幕上没有说，人只会觉得点了两个地方看到同一页。

### U. 变量字典把「秒数」这种字段也报成「词表未发布」

「特征体系」里，时长、目标时长这类**数值字段**，「词表」列写的是「未发布」，点开还配一整段警告：「这个字段现在接受任何取值，在发布之前，它每多用一次就多一分散开的可能」。

数值字段本来就不该有词表。后端自己是分清楚的——顶上那句「76 个枚举字段还没发布词表」只数枚举字段，同一份代码里还专门注释了「数值字段每条都不一样是设计意图」。只有列表列和详情面板没按这个口径来，所以同一屏上两个数字算的不是一回事。

### S. 找相似的空态说了两遍

「库里没有在这些变量上和它一致的素材。」紧接着「没有在这些变量上一致的素材。」

另外，拿一条提取失败、只剩 2 个变量的素材当种子时，页面照样给出一个干干净净的否定结论——没有提醒这条种子本身就不够格。

### T. 已失效素材在两处待遇不一致

找相似明确拒绝拿已失效素材当种子（代码注释写了理由：「拿一条已经不作数的素材去找相似，找回来的一组从一开始就不该用」）。而素材映射的「改归属」下拉里，那 3 条已失效素材照样列出来可选。

## 修复与复验结果（2026-08-13 回填）

25 条（A–X）加复验新发现的 Y、Z 系列全部修完，并按用户视角 + PRD 逐入口重走一遍。
PRD 冲突的处理结论写在[对照文档](./2026-08-12-素材洞察走查问题对照PRD.md)的「处理结论」一节。

### 复验时新发现、也一并修掉的

| 现象 | 根因 | 处置 |
|---|---|---|
| 判定阈值对**所有人**永久锁死，提示写「你现在是当前角色」 | 登录时的会话态丢掉了 `actor.scopes` 和组织信息，`hasScope` 恒为 false；兜底文案把占位词当角色名 | `api.ts` 的会话装配补上 scopes，并补取 `/organizations` 拿组织与角色；角色措辞统一走 `roleSentence`，读不到就直说读不到 |
| 权限不够时界面弹英文（`The required permission scope is missing.` / `insights.confirm scope is required`） | 后端两处拒绝都是英文原文，前端直透 | API 层加 `permissionMessage()` 统一翻成中文并指向「设置 · 确认权限」，一次覆盖所有确认类入口 |
| 同一条素材既算进「已经能拿来解释的」，又挂在「提取失败」队列里 | 队列数 `failedRuns`（最新一次运行失败），对账行数 `failedExtraction`（状态门）；跑挂后有人手工补了变量，两个口径就打架 | 队列只数**还挡路的**失败（`blockingFailures`），已经不挡路的降级成一行小字 |
| 素材详情对已经有变量的素材说「这条素材现在一个变量都没有」 | 失败文案无条件写死 | 按 `features.length` 分支：有变量就说清这些变量不是这一次提的 |
| 外部素材页写「这里不能上传文件」，列表却写「原件留到 2026/11/10」 | 旧版 `externalStorageKey` 在没有扩展名时也拼出一条路径，库里留下两行"幽灵原片" | 代码侧已修（没有文件就返回空串）；本地演示库的两行脏数据用 SQL 清掉 |
| 数据体检显示「接入未启用· 数据正常」，分隔符少一个空格 | JSX 表达式跨行时把换行连同缩进一起吃掉 | 合并成一行写，并在注释里写明原因 |
| 改动史写「改了 3 格」，实际只动了 1 格 | 存的是整版快照，被读成"这一次动了几格" | 改成「这一版有 N 格不走出厂设定」 |

### 验证

- `go test ./internal/systems/insights/` 通过。

### 需要知会的两处改动

1. **动了会话态的读取口径**（`src/data/api.ts`，属认证相关）：登录/取会话时多请求一次
   `/platform/v1/organizations`，把 scopes、组织、角色一并落进会话。读不到组织不影响登录——
   权限判断只依赖 scopes，组织名只影响顶栏那一行显示。
2. **清理了本地演示库两行数据**：
   `update cookies.insight_external_assets set storage_key='' where storage_key<>'' and storage_key not like '%.%';`
   只影响本地演示库，清的是旧代码遗留的幽灵路径。
