# 第一部分 · 主旨与总体结构

## 1.1 主旨

> **投完一轮，说清楚为什么，把结论存下来，下一轮直接用。**
>
> 样本永远不够，所以要能从库里拉相似素材把样本做厚。

投放素材做出来之后会发生两件事：钱花出去了，数据回来了。但回来的数据和当初做素材的决策是两套互不相通的东西——报表里是「广告 AD-1001，花了 2.4 万，点击率 3.2%」，做素材的人记得的是「那条是数字人口播、痛点开场、15 秒」。没人把这两边对上，所以每一轮都在凭印象重来。

这个模块把两边接起来，并且让接起来的结论能留下来、下一轮能用上。

## 1.2 为什么要重构

改之前是 11 个一级入口、5 个分组，主线要跨 8 个页面。四种「乱」同时存在：入口太多找不到路、单页信息过载、概念和名词太多、代码结构乱（两个组件文件分别 1821 行和 1554 行）。

根子在于**组织轴错了**：现在的入口是按「系统里有哪些东西」排的（数据源一个、素材一个、实验一个、报告一个、经验一个），但人干活是按「一件事」走的——「这批素材投完了，到底怎么样？」

**重构的核心是换轴：从「按对象组织」改成「按一件事组织」。**

## 1.3 用户只需要认识 4 个东西

界面上只出现这四个，其余（AnalysisCohort、AnalysisMetricSnapshot、AssetIndex、ProjectAssetLink、洞察卡、Variant、SampleCheck……）全部降为内部实现，用户永远不需要知道。

| 对象 | 一句话 | 用户什么时候碰它 |
|---|---|---|
| **素材** | 一条可分析的创意 = 内容变量 + 投放数据 + 来源。**素材本体在素材库（创意那边），这里只是贴在它上面的分析索引** | 数据不对、有新素材进来 |
| **复盘** | 一批素材 + 一个时间窗口 → 收拢成一份可交付的结论 | 一轮投完，收口的时候 |
| **经验** | 被人确认过的结论，带适用条件和证据 | 下一轮做素材前 |
| **实验** | 为验证一个变量专门做的对照 | 看数看到说不清原因时 |

**「分析」是个动作，不是对象**——它是一个页面，不产生需要用户管理的东西。用户在分析页唯一会攒下来的是「记的笔」，那些笔属于当前复盘，不是第五个对象。

## 1.4 中轴：三档结论

这是把散落概念统一起来的关键。**同一套三档，在所有地方都是同一个意思。**

| 档 | 含义 | 能拿它干什么 |
|---|---|---|
| ✅ **能归因** | 两边只差一个变量，样本也够 | 可存成经验，可指导下一轮 |
| 👁 **只是观察** | 差异真实存在，但变量混在一起 | 只能记录，不能当结论用 |
| ❓ **算不出来** | 样本不够或天数不够 | 不显示任何对比数字 |

**三档不只是一个标签，是模块的通用语言，且各自有明确出口：**

```
复盘里每条结论    带一档
经验卡上          带一档（继承自它来源的结论）

👁 只是观察  ──[做个实验]──▶  ✅ 能归因
❓ 算不出来  ──[找相似素材]─▶  👁 只是观察  或  ✅ 能归因
```

实验和相似素材因此不是两个孤立功能，而是**两条明确的升级通道**。用户看一眼就知道自己卡在哪、下一步该点什么。

## 1.5 五个入口

| 入口 | 吸收了原来的 | 定位 |
|---|---|---|
| **分析** | 投后分析（六视图） | 自由探索，看数不下结论 |
| **复盘** | 报告中心、实验中心 | 收口：把发现固化成经验 |
| **经验** | 经验库、投前洞察 | 同一批数据两种读法：查 / 管 |
| **素材** | 数据接入、分析素材库、内容分析 | 备料 |
| **设置** | 系统设置、数据质量、能力运营 | 低频治理 |

**11 个入口 → 5 个。**

### 为什么分析和复盘要分开

**看数和下结论是两种心态。**

- **探索**：我随便翻翻，切个窗口，换个维度，先看疲劳再回头看对比，再点进某条素材看趋势。要的是**自由跳转**。
- **收口**：我要交一份东西出去。要的是**固定叙事**。

把探索塞进一个「五段固定顺序往下滚」的页面，等于压抑探索；把收口做成「再看一遍所有数」，等于让人做两遍功。两个入口，各自只干一件事。

频率也不同：看数可能天天看，复盘一轮一次。

**这不是把主线变成两页。** 关键在于「记一笔」——用户在分析页任何一屏都能就地把一条发现钉住，复盘页收的是这些钉住的发现，不重新展示所有数。现有代码里的 `FreezeReportAction.tsx`（定格这一屏 → 报告中心）就是这条路，本设计沿用并强化。

## 1.6 全模块数据流

```
平台内：【素材库】（创意 / 平台的，洞察不建）
平台外：【外部素材证据区】（洞察自己存，只读 · 有保留期）
   └─▶ 【素材】给两边都建分析索引，补齐三样：
          对上号 · 内容变量 · 投放数据
          └─▶ 【分析】六视图自由探索，每屏自动标三档
                 ├─ ✅ 能归因    ─▶ [记一笔]
                 ├─ 👁 只是观察  ─▶ [做个实验] ─▶ 升级为 ✅ ─▶ [记一笔]
                 └─ ❓ 算不出来  ─▶ [找相似素材] ─▶ 重判 ─▶ [记一笔]
                        └─▶ 【复盘】记下的发现 + 系统结论 → 勾选提交
                               └─▶ 人工确认 ─▶ 【经验】下一轮查
```

# 第二部分 · 五个模块

---

## 模块一 · 分析

### 做什么

自由探索投放数据。**六个视图，任意切窗口、选素材、换维度，随便跳。**

这一页承接原来的「投后分析」，六个视图基本原样保留——**探索页不需要讲故事，所以不重排**。改的是视图内的表达：每条发现自动带三档标记、名词换成业务词、方法名收进「怎么算的」。

### 一条铁律：分析页不下结论

这一页的产出只有一种东西——**被钉住的发现**。它不写经验、不改任何东西的状态。要固化，去复盘。

这条界线是「分析」和「复盘」能分开的前提。含糊了，两页就会互相长成对方。

### 六个视图

| 视图 | 回答什么 | 怎么算的 |
|---|---|---|
| 指标总览 | 这个窗口整体花了多少、效果如何 | 汇总，带口径说明和数据缺口标注 |
| 素材对比 | 两条素材谁更好，差异算不算数 | 两两配对 + 三档判定；异常日剔除并说明 |
| 趋势 | 逐日走势 | 按天序列。**不足 4 天判「看不出来」** |
| 疲劳 | 素材是不是在衰退 | 窗口切前后两半比**日均**，三条阈值判定 |
| 异常 | 哪天的数据不正常 | MAD，偏离超 3.5 倍算异常。**不足 5 天不判** |
| 驱动因素 | 差异是哪个内容特征带来的 | 按素材特征分组对照（有这个特征的 vs 没有的） |

> 用 MAD（中位数绝对偏差）不用标准差，是因为标准差会被异常点自己抬高——越异常反而越不容易被发现。

### 每一屏都带三档 + 就地补救

三档结论首次出现在这一页，跟着数据走，系统自动标：

```
素材对比
  「痛点开场」比「产品开场」点击率高 38%
   ✅ 能归因 · 4 组对照 · 两边只差这一个变量
   怎么算的                              [记一笔]

  15 秒整体好过 30 秒，但口播风格也不同
   👁 只是观察 · 变量混杂
                          [做个实验]     [记一笔]

  数字人 vs 真人：各 2 条
   ❓ 算不出来 · 样本不足，还差 4 条
                          [找相似素材]
```

**两条升级通道都在这一页就地可用**——探索时发现卡住，当场补救，不用等到复盘：

- 👁 只是观察 → `做个实验`，系统带着变量预填一个只改一个变量的对照实验
- ❓ 算不出来 → `找相似素材`，从库里拉结构相似的扩样本，当场重判

### 用户怎么用

**场景：想看看夏季推广这半个月投得怎么样。**

1. 进「分析」，选项目和窗口 7/15–7/31
2. 先点「疲劳」，看到 A-1 在掉 → 点进 A-1 看趋势，确认是真的在掉不是某天数据问题
3. 回「素材对比」，看到「痛点开场」那条是 ✅ 能归因 → **`记一笔`**
4. 看到「15 秒 vs 30 秒」是 👁 只是观察 → 点 `做个实验`，预填了一个实验，提交
5. 看到「数字人 vs 真人」是 ❓ 样本不足 → 点 `找相似素材`，库里捞出 9 条，勾选纳入，当场重判成 ✅ → **`记一笔`**
6. 回「疲劳」，把 A-1 那条也 **`记一笔`**

**三笔记完，去复盘收口。**

### 记的笔去哪了

用户在分析页从头到尾**不需要知道「复盘」这个东西存在**。他只是在看数、随手钉住几条。

规则是：**一笔落到「（项目 + 时间窗口）对应的那个未提交复盘」上**，没有就自动建一个草稿。所以用户第一次点「记一笔」，系统悄悄建了复盘草稿；他换个窗口再记，记到另一个草稿上。

这样做的代价是可能攒出一堆没人收口的草稿。处理办法：**草稿不出现在复盘列表里**，只有第一次进复盘页并动过它之后才转正；30 天没动过的空草稿自动清掉。

> 反过来的设计——「先建复盘，再进分析页记笔」——被否掉了：那等于要求用户在还没看数之前就宣布「我要开始复盘了」，而看数往往是随手的。

### 能做到什么 / 做不到什么

| 能 | 不能 |
|---|---|
| 六视图自由跳转，任意切窗口和素材范围 | 不做多因子分析（AM-019 后置） |
| 每条发现自动三档判定，带证据和「怎么算的」 | 不排受众变化（没有受众数据），疲劳只列「排除不掉的解释」 |
| 就地发起实验、就地拉相似素材扩样本 | **不写经验、不改状态**（铁律） |
| 任一屏「记一笔」，收进当前复盘 | 不做同环比（没有历史窗口的可比口径） |

### 要建什么

- 新页面 `analysis/`，六个视图共用一次数据请求（沿用现有做法，避免「趋势里看到的」和「疲劳里算的」来自两个时刻的快照）
- 三档判定收敛到唯一实现（扩 `group_compare.go`）
- 「记一笔」：沿用并强化现有 `FreezeReportAction.tsx`，定格的不再是整屏，而是**一条带证据的发现**
- 「做个实验」「找相似素材」两个就地动作
- **必修**：疲劳的曝光变化改为比日均，不比总量（见 §3.5）

## 模块二 · 复盘

### 做什么

收口。一个复盘 = 一个项目 + 一个时间窗口 + 一批素材，产出是**一份可交付的复盘 + 若干条待确认经验**。

这一页吸收了原来的「报告中心」和「实验中心」。

**它不重新展示所有数**——数在分析页。这里只有三段：摘要、发现、下一轮。

### 用户怎么用

**场景：在分析页记了三笔，现在收口。**

1. 进「复盘」，看到刚才记的三笔已经在②里，另外系统自动补了 2 条它算出来但没人记的结论
2. ① 扫一眼摘要，注意到「3 条素材数据只到 7/29，下面结论按 15 天算」
3. ② 五条发现按三档归好堆。勾选 ✅ 的 3 条，各补一句适用条件
4. ③ 提交 → 变成待确认经验，等有权限的人确认
5. 第 4 步那个实验跑完后，结论自动回流到这个复盘的②，可以再勾选一次

### 页面结构

```
┌─────────────────────────────────────────────────────┐
│ 复盘：夏季推广 · 7/15–7/31 · 12 条素材       [新建] │
├─────────────────────────────────────────────────────┤
│ ① 这一轮怎么样                                      │
│    花了 24,300 · 曝光 82 万 · 点击率 3.1%           │
│    ⚠ 3 条素材数据只到 7/29，下面结论按 15 天算      │
│    ⓘ 7/22 数据不正常，已从判定中剔除                │
├─────────────────────────────────────────────────────┤
│ ② 发现（5）        ● 我记的 3   ○ 系统补的 2        │
│  ✅ 能归因（3）                                      │
│   ☑ 「痛点开场」比「产品开场」点击率高 38%    ●     │
│      └ 4 组对照 · 只差这一个变量     怎么算的       │
│   ☑ 数字人比真人点击率高 22%                  ●     │
│      └ 13 条素材（含库内相似 9 条）· 跨 3 个项目    │
│      └ ⚠ 混杂：这 3 个项目渠道不同                  │
│   ☑ A-1 疑似疲劳：点击率 3.3%→1.8%            ●     │
│  👁 只是观察（1）                                    │
│     15 秒好过 30 秒   ⏳ 实验进行中，结论回流后再看  │
│  ❓ 算不出来（1）                                    │
│     首帧有无人脸：各 1 条，样本不足           ○     │
├─────────────────────────────────────────────────────┤
│ ③ 下一轮怎么做                                      │
│    已勾选 3 条 · 各补一句适用条件                    │
│    [提交]  → 待 XX 确认后进经验库                   │
└─────────────────────────────────────────────────────┘
```

### 三段各自做什么

| 段 | 回答什么 | 能做到 | 做不到 |
|---|---|---|---|
| ① 这一轮怎么样 | 整体规模和数据可信度 | 汇总花费、曝光、点击、转化；数据缺天和异常日的标注在这里统一说明，②里所有结论继承 | 不重复分析页的六视图，要看数点回分析 |
| ② 发现 | 这一轮到底得出了什么 | 用户记的 + 系统自动算的，合并去重，按三档归堆；标出哪些是人记的、哪些是系统补的；实验未回流的挂「进行中」 | 系统不自动勾选，勾哪条是人的判断 |
| ③ 下一轮怎么做 | 把结论固化 | 勾选 ✅ 结论 → 补适用条件 → 提交为待确认经验 | 不自动确认，必须人工（见 §3.2） |

### 为什么系统还要「补」发现

用户记的是他注意到的，系统算的是全量。②把两边合起来，是为了**防止漏掉人没看到但系统算出来的结论**——尤其是 ❓ 算不出来那一档，人不会主动去记「这条我算不出来」，但它恰恰是下一轮该补样本的地方。

标出「● 我记的 / ○ 系统补的」，是让人知道哪些是自己过过脑子的。

### 实验为什么不做一级入口

实验只有一个入口：分析页 👁 那一档旁边的「做个实验」。实验列表做成复盘页的抽屉。

**理由：没人会先想「我要做个实验」再去找变量——永远是先发现说不清，才需要实验。** 做成一级入口，等于要求用户自己想起来该做实验，而系统明明已经知道哪条结论卡住了。

实验的规则不变：样本不达标时 `Result` 为 nil，**一个对比数字都不显示**，也不允许下结论；对比引擎与分析页共用一套（`group_compare.go`），两边不可能给出互相矛盾的判定。

### 要建什么

- 新页面 `review/`，三段
- 收「记一笔」落下的发现（表结构见 §4.3）+ 系统自动补算的发现
- 发现合并去重：用户记的和系统算的可能是同一条，按（对比维度 + 变量）去重，保留人记的那条并标注
- 实验结论回流到复盘②
- 一次读接口拿全三段

## 模块三 · 经验

### 做什么

经验是**被人确认过的结论**，带适用条件和完整证据。这一页把原来的「经验库」和「投前洞察」合并——它们本来就是同一批数据的两种读法。

### 用户怎么用

**场景 A（查，最高频）：下一轮要做素材，想知道以前什么有效。**

进「经验」，默认「查」模式，系统按当前项目条件（品牌、渠道、广告类型）自动筛，列出适用的经验。看到「痛点开场比产品开场点击率高 38%」，点「凭什么」展开，看到 4 组对照、12 条素材、15 天窗口，再往下点能看到具体是哪 12 条素材、来自哪次复盘。照着做下一条。

**场景 B（管，低频）：有人提交了新的待确认经验。**

切「管」模式，看到「待定」里有 2 条。逐条看证据，确认 / 驳回 / 或者觉得依据不足——点「修订」补齐适用范围、数据依据、内容依据，提交。修订是**新增一个版本**，原件保留。

### 页面结构

```
┌─ [查] ── 管 ───────────────────────────────┐
```

## 模块四 · 素材

### 做什么

给复盘备料。一条素材要能进复盘，必须齐三样：**对上号**（素材 ↔ 平台广告 ID）、**内容变量**（拆成可比较的东西）、**投放数据**。

这一页吸收了原来三个入口：数据接入、分析素材库、内容分析。

### 第一条边界：这一页不是素材库

**素材库不归洞察。** 文件、预览图、时长画幅、版本、衍生关系、权利证明、生成血缘——这些都在平台素材库（`internal/platform/assets/`）里，创意模块通过 `IngestRenderedVideo` 往里写（`creative/render.go:52`），**到时候是从创意创作那边接过来的**。

洞察这一页只建**索引层**：在别人的素材上贴三样自己的东西。

| | 归谁 | 放什么 |
|---|---|---|
| **素材库** | 平台 / 创意 | 文件、预览、时长画幅、版本、衍生关系、权利、生成血缘 |
| **分析索引** | 洞察（本模块） | 对上号 · 内容变量 · 投放数据 · 分析状态 |

这不是我定的，是文档定的：`03:86`「分析素材库只包含分析索引和版本引用，**不承担通用文件管理**」「不扩张成网盘导航」；`23-strategy-creative-parallel-contracts-v2.md:91`「项目素材库是 **Creative** 的支持页面」。

> **现状是断的。** `internal/systems/insights/` 根本没 import `platform/assets`，只在 `assets.go:179` 存了 `PlatformAssetID` + `PlatformAssetVersion` 两个裸字段——**记了个号码，没有真链接**。所以现在点一条分析素材，看不到它的预览、时长、版本，也看不到它是从哪一版改出来的。第 3 期要接的就是这条线。

**页面上的表现：** 素材卡点开，上半截（预览、时长、版本、血缘）是从素材库读的，右上角一个「去素材库」；下半截（内容变量、投放数据、分析状态）才是洞察自己的。**两截视觉上分开**，让人知道哪些东西改了要去别处改。

### 第二条边界：外部素材不进素材库，单独存成「证据」

**创意侧明确不接受平台外素材进素材库**（2026-08-11 确认）。这个反对是对的，不只是洁癖——创意的人搜素材是为了做新素材，搜出来一堆不能用的竞品视频是纯噪音。

而且这两样东西**本来就不是一类**：

| | 素材库里的素材 | 平台外素材 |
|---|---|---|
| 是什么 | **资产**：要复用、要再剪、要投放 | **证据**：只为算这一次数 |
| 权利 | 我们自己的 | 别人的，只有分析用途 |
| 生命周期 | 长期 | 跟着复盘窗口走 |
| 谁会去找它 | 创意做新素材时 | 没人主动找，只在对比里出现 |

**所以外部素材归洞察自己存，但用五条约束锁死在「证据」这个身份上，不让它长成第二个素材库：**

1. **不产生 `ProjectAssetRef`**——创意侧任何检索、任何引用都碰不到，他们库里一条都不会多
2. **只读**：没有版本、没有衍生、没有替换、没有重命名、没有文件夹。导进来什么样就什么样
3. **有保留期**：原片默认留到复盘窗口结束 + 90 天，到期自动清，**只留派生物**（封面帧、关键帧、转写文本、提取出的变量、投放指标）。变量和指标永久保留——经验库要追溯证据，但证据可以是「当时提取出的变量」，不必是原片
4. **导入时勾一条用途声明**：仅用于平台内部分析对比，不用于再创作、不对外分发。是记录，不是审批
5. **页面上和平台内素材视觉分开**，明写「外部素材 · 仅用于分析对比」

存储**复用 `platform/assets` 的 blobstore 实现**（`blobstore.go` / `tos_blobstore.go`），但**不走 assets 的建档流程**——同一个轮子，不同的库。

**这条也满足 `internal/integrations/crawler/README.md` 的规矩**：那里说「第三方内容必须经过明确授权导入才能变成 Assets 记录」——本设计下外部素材**根本不会变成 Assets 记录**，规矩天然成立；授权那层意思由第 4 条的用途声明承接。

> **要认下来的代价：保留期一到清了原片，第 7 期的时间轴就补不回来了。** 早于保留期导入的外部素材没法回头抽分镜和口播。接受这个代价，理由是外部素材本来就是为当轮比较服务的，90 天前的再深挖价值不大。90 天是拍的数，有合规既定口径就按口径改。

### 第三条边界：三条来源分开算，不合并

来源不同，三步的**难度完全不同**，混在一起讲会让人以为工作量一样：

| | ① 平台内（我们生成的） | ② 平台外（千川等拿进来的） | ③ 爬来的 |
|---|---|---|---|
| 素材怎么进来 | 创意模块产出，**已经在素材库里了** | 上传 / 平台导出，进**外部素材证据区**，不进素材库 | **本期不做**，见 §6.4 |
| 文件归谁 | 素材库（创意/平台） | 洞察，且有保留期 | — |
| 投放数据怎么进来 | 投放模块回流 | 平台报表导出 | — |
| **对上号** | 基本自动，我们自己投的 | **重点难点**，对不上后面全错 | — |
| **内容变量** | 制作参数本来就知道，**直接带过来**，标 `human` | **必须靠模型提取**，标 `ai`（未确认前不进归因，见 §3.4） | — |
| 能不能进归因 | 能 | 变量得有人确认过才能 | — |

### 页面结构

```
┌──────────────────────────┬──────────────────────────┐
│ 平台内素材   8            │ 外部素材   47             │
│  ← 创意模块 · 素材库      │  仅用于分析对比 · 有保留期 │
│                          │  巨量千川 32 · 快手 15    │
├──────────────────────────┼──────────────────────────┤
│ ✓ 已建索引      8        │ ✓ 已导入        47       │
│ ✓ 变量已带入    8        │ ⚠ 对不上号       6  先处理│
│ ⚠ 投放数据未回流 3       │ ⚠ 待提取变量    12       │
│                          │ ✗ 提取失败       2       │
│                          │ ⏳ 30 天内原片到期  5     │
└──────────────────────────┴──────────────────────────┘
                     ↓ 汇合
               可分析素材  55 条 → 进分析 / 复盘
```

**两栏不只是分类，是两种所有权。** 左栏的数字是素材库里已经有、洞察这边建好索引的，洞察一个字节都没存；顶上「← 创意模块 · 素材库」可点，跳过去看原库。右栏的文件是洞察自己存的，所以才有保留期这一行——**到期提示放在这里，是让人有机会在原片被清掉之前做完想做的分析。**

### 用户怎么用

**场景 A：复盘里发现素材少了。**
进「素材」，一眼看到「对不上号 6 条」红色置顶。点进去，逐条把平台广告 ID 和我们的素材版本对上，对完自动进可分析池。

**场景 B：从千川导了一批素材和报表进来。**
在「外部素材」栏点导入 → 选平台「巨量千川」→ 上传视频包和报表 → 勾用途声明（仅用于分析对比，不用于再创作和对外分发）→ 文件进**外部素材证据区**（不进素材库）→ 建索引、跑映射、排队提特征。三个队列的进度都在这一栏里看，旁边显示原片到期日。

**场景 C：想看某条素材到底是怎么做的。**
点进任意一条素材 → 单素材拆解页。上半截（预览、时长、版本、血缘）读素材库，下半截（变量、投放数据）是洞察自己的。

### 能做到什么

- 在素材库已有素材之上建立分析索引，来源可追（AM-001。**素材本身的稳定 ID 和版本是素材库给的，洞察不重新造一套**）
- 导入投放数据，展示口径和新鲜度（AM-002）
- 平台创意/广告 ID ↔ 素材版本映射，对不上进待处理队列（AM-003）
- 识别六类素材类型（小红书图文、公众号图文、品牌广告、数字人、广告前贴、爆款复刻）（AM-004）
- 按类型调模型提取内容特征，六套提取规格（AM-005）
- 人工批量确认、修改、拒绝特征，**人工结果不被模型覆盖**（AM-006）
- **相似素材检索**（AM-017，新建，见 §3.3）

### 三处实质改动

**1. 把和素材库的连接做实。**
现在 `PlatformAssetID` / `PlatformAssetVersion` 是两个裸字段，没有真引用。改成对 `platform/assets` 的实引用，且**建索引时校验对象存在**——号码对不上直接拒绝建索引，而不是先建了、点开一片空白。这是「素材库从创意接过来」这件事在洞察这边的落点。

**2. `Platform` 枚举加「巨量千川」。**
现在只有抖音 / 快手 / 小红书 / 公众号 / 腾讯广告 / 其他。千川是电商投放，和抖音自然内容不是一回事，指标口径也不同，必须单列。

**3. 平台内素材不走模型提取。**
现在不分来源一律走模型。对自己生成的素材这既浪费又不准——模型看视频猜出来的「15 秒、痛点开场」，不如创意模块里本来就记着的那份。改成从创意模块直接带制作参数，标记为 `human` 来源（等同人工确认，不被模型覆盖）。

**这三条合起来才是「素材库接过来」的完整含义**：连接做实（1）、来源分开（2）、平台内直接吃创意的制作参数不再让模型重猜（3）。只做 1 不做 3，等于接过来了却不用。

### 单素材拆解（分两期）

**现在（第 3 期）：** 扁平字段表 + 投放数据。字段来自六套提取规格，例如「广告前贴」是 22 个字段（15 个效果广告通用 + 7 个前贴专用）。

**后置（第 7 期）：时间轴 + 叙事拆解。**

现在的模型是「一条素材 = 一袋标签」。真正有价值的深度拆解要的是「一条素材 = 一条时间轴」：

```
   0s ──────────────────────────────── 12s
分镜 │1│2│ 3 │4│ 5 │6│ 7 │8│  9  │      9 个分镜，各自起止 + 一句画面描述
口播 ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬      转写文本 + 时间戳
情绪  惊讶─心疼──愤怒──谴责──争议        情绪节点 + 触发时间点
```

**有了时间轴，一大批变量从「模型猜的」变成「算出来的」：**

| 变量 | 现在 | 有时间轴之后 |
|---|---|---|
| 单位时间信息量 | 模型估一个数 | 分镜数 ÷ 时长 |
| 镜头节奏 | 快/中/慢三档 | 镜均 1.3 秒 |
| 语速 | 前贴没有这个字段 | 80 字 ÷ 12 秒 = 6.7 字/秒 |
| 情绪强度 | 没有 | 5 个节点 / 12 秒 |
| 钩子占比 | 没有 | 12 秒 ÷ 全片时长 |

**算出来的数才能跨素材比。**模型估的数放进归因，等于把不确定性混进证据链。

叙事拆解（分节讲钩子怎么设计的、画面和口播怎么配合的、情绪怎么起伏的）是**把时间轴讲成人话**，不是另一份数据。两者互相能点：拆解里读到「12s 内 9 个分镜」→ 点一下跳到时间轴；复盘里看到「镜均 1.3 秒的素材更好」→ 点一下回到具体分镜。

**这一期整体后置，但第 1 期和第 3 期各留一个钉子（见 §3.4 和 §5），到时候是接上去，不是改回来。**

### 要建什么

- 新页面 `assets/`：两栏概览 + 映射队列 + 提取队列 + 单素材拆解（上下两截，分属素材库和洞察）
- **接通 `platform/assets`**：裸字段 → 真引用，建索引时校验对象存在（只对平台内素材）
- **外部素材证据区**：单独一张表 + 单独存储前缀，复用 blobstore 但不产生 `ProjectAssetRef`；只读、有保留期、到期清原片留派生物；导入时记用途声明
- `Platform` 加 `qianchuan`
- 平台内素材走「创意模块带入」而非模型提取
- 相似素材检索（第 4 期）
- 时间轴空表（第 3 期建，第 7 期填）

**不建什么**（写出来是为了防止下一个人手痒）：文件管理、文件夹、回收站、上传/替换文件、权利审批、预览图生成、转码。这些全在素材库那边，`03:86` 明令「不扩张成网盘导航」。

## 模块五 · 设置

### 做什么

这个模块自己的参数。三合一的逻辑：**数据质量是「配置对不对」的体检报告，能力运营是变量字典的维护，系统设置是判定阈值——都是同一件事。**

```
① 判定阈值   多少天算够 · 跌多少算疲劳 · 偏离多少算异常   ← 改为可写
② 数据体检   新鲜度 · 缺失 · 口径 · 修复队列
③ 变量字典   特征体系 · 指标口径
④ 确认权限   谁能确认经验
```

### 用户怎么用

**场景：觉得「跌 20% 才算疲劳」太松了。**
进「设置」→ 判定阈值 → 把点击率下滑门槛从 20% 改成 15% → 保存。回到复盘，判定跟着变，且页面上标出「本次判定使用的阈值」。

### 能做到什么

- 19 个阈值**可读可写**（改之前只读，写死在代码常量里）
- 数据新鲜度、缺失、口径校验、修复队列
- 特征体系和指标字典的治理
- 确认权限配置

### 为什么阈值必须可写

这些阈值直接决定三档结论怎么判——**不能改就等于这个模块的判断标准不可调**。不同行业、不同渠道的合理门槛不一样，写死一套是错的。

改为可写之后必须配套：**每条结论都记录它是用哪套阈值判出来的**，否则改了阈值之后历史结论说不清是按什么标准算的。

### 要建什么

- 新页面 `settings/`，四组
- 阈值落库（现在是代码常量），带版本
- 结论记录所用阈值版本

# 第三部分 · 贯穿全模块的规则

## 3.1 三档结论的判定，全模块只有一处实现

`group_compare.go` 已经是公用的（实验中心和素材对比共用），扩成全模块唯一判定入口。分析页六视图、复盘②③、实验、相似素材扩样本后重跑，走的都是同一套。

**这样不可能出现两个页面对同一条结论给不同档位。**特别是：用户在分析页「记一笔」记下的那条发现，到了复盘页不会换档——因为档位是跟着数据算的，不是跟着页面走的。

## 3.2 拒绝下结论（这个模块的灵魂，一条不能丢）

| 情况 | 怎么表现 |
|---|---|
| 样本不够 | **不显示任何对比数字**，显示「还差多少」+ 拉相似素材的入口 |
| 数据缺天 | 在①里说明「按 15 天算」，所有下游结论继承这个标注 |
| 两个方向打架 | **拒绝推任何一个方向**，改为指向实验 |
| 素材对不上号 | 素材页红色置顶，且该素材不进复盘 |
| 模型没配置 | 直接报错，不用模板糊弄 |
| 不足 4 天 / 5 天 | 不给趋势结论 / 不判异常 |

这是这个模块和 BI 报表的根本区别——**BI 给你数字，这个给你敢不敢信这个数字。**

## 3.3 相似素材：样本不足的解药

真实项目一轮就十几条素材，绝大多数比较都会掉进「样本不足」。这一档现在是死路，也是「一屋子功能却感觉用不上」的真正原因。

```
❓ 数字人 vs 真人：本轮各 2 条，样本不足
   [从库里找相似的]
        ↓
   库里另有 9 条结构相似（同为痛点开场 + 15 秒 + 有商品露出）
   数字人 5 条 / 真人 4 条，来自 3 个项目、2 个渠道
   ☑ 纳入本次比较
        ↓
   ✅ 能归因：数字人点击率高 22%（共 13 条，跨 3 个项目）
   ⚠ 混杂因素：这 3 个项目渠道不同，已列出
```

**相似用「内容变量重合度」算，不用向量。** 两个理由：

1. 特征体系已经落库，拿现成的，不需要新基建
2. **更关键：重合度能写出理由。**「这两条都是痛点开场 + 15 秒 + 有商品露出」可以直接进证据链，用户点得进去。向量给的是 0.87，说不出为什么像——而这个模块的第一原则就是结论必须能追溯到证据，一个说不出理由的相似度会污染整条证据链。

向量召回（`docs/07-unified-model-provider.md` 的 `embedding.generate`、`docs/23` 的 `similarity_group`）以后可作为补充召回，但不能当主路径。

**这也说清了平台外素材的价值**：外部素材不是我们投的，它们的用处就是**把比较基数做厚**。

第 7 期时间轴接上后，相似度还能算「节奏形状相似」「情绪链条形状相似」，理由依然说得出人话。

## 3.4 变量分三类，决定能不能进归因

`FeatureSource` 现在只有 `ai` / `human`，**加第三种 `derived`（算出来的）**。

| 类型 | 来源 | 能进归因吗 |
|---|---|---|
| `derived` 算出来的 | 从时间轴/投放数据直接计算 | ✅ 可以 |
| `human` 人工确认的 | 人填的，或人改过模型结果的 | ✅ 可以 |
| `ai` 模型判断未确认 | 模型提取，没人看过 | ❌ **不进归因**，只展示 |

**这一条必须在第 1 期定下来。** 原因：`info_per_second`（单位时间信息量）现在是模型估一个数。如果它就这么进了归因，将来改成从时间轴算出来，所有用过它的历史结论都得重算——而经验库是「新增版本不覆盖、历史可审计」的，那些基于模型估数的经验会永远挂在账上，说不清是对是错。

定下这条规则，等于给未来的时间轴留好入口：时间轴一接上，派生变量自动是 `derived`，直接可用于归因，不用改归因逻辑。

## 3.5 顺手必修的两件

**一、疲劳的曝光变化改为比日均。**
窗口切前后两半时，天数是奇数会切成「前 3 天 / 后 4 天」，后半段天生多一天，曝光凭空多三分之一，刚好压过「涨 10% 算放大」这条线。当前页面上那个 +40.6% 就是这么来的，不是在放量。

后果不只是数字难看：疲劳判定第一条规则就是「曝光在放大 + 点击率在跌 = 最典型的疲劳」。接了真实数据、某条素材点击率下滑 20%，系统会直接盖章「疑似疲劳」，哪怕投放量一动没动。

改成比日均，天数差异自动抵消。只动疲劳一处，半小时。

**二、导入 21 天演示数据。**
`scripts/seed-insight-performance-demo.sh` 会生成 21 天、四条刻意设计的曲线（含一条标准疲劳形态：点击率 3.3% → 1.8%、曝光 8000 → 18000）。这份数据没有导入过当前项目，素材名对不上。

现在库里只有 3 条素材 × 7 天，且点击率几乎是直线——**疲劳、异常、驱动因素这三块等于从来没验证过。**

## 3.6 名词表

页面上只出现右列写法。**原则：只出现业务词，方法名一律收进结论旁边的「怎么算的」。**

| 现在 | 改成 |
|---|---|
| 归因阶梯 | 能归因 / 只是观察 / 算不出来（直接当小标题） |
| MAD 异常检测 | 「这天数据不正常」，方法收进「怎么算的」 |
| 九字段洞察卡 | 卡面三行（结论 / 适用条件 / 凭什么），其余点开 |
| 候选 / 已确认 / 待复审 / 已失效 | 待定 / 在用 / 停用（复审到期在「在用」里标黄） |

# 第四部分 · 技术结构

## 4.1 前端

把洞察相关部分从 `SpecializedPages.tsx`（1821 行）和 `Pages.tsx`（1554 行）里拆出来，一页一目录：

```
src/components/insight/
  analysis/     分析：六个视图各一个组件 + 一个共用数据 hook
  review/       复盘：三段各一个组件 + 一个数据 hook
  experience/   经验：查 / 管 两个模式
  assets/       素材：两栏 + 映射队列 + 提取队列 + 单素材拆解
  settings/     设置：四组
  shared/       三档结论徽章 · 证据抽屉 · 「怎么算的」弹层 · 样本不足占位 · 「记一笔」按钮
```

`shared/` 是三档中轴的落地处——同一个徽章组件在五个页面用。「记一笔」也放这里：它要出现在分析页六个视图的每一屏，不能各写一份。

## 4.2 后端

44 个接口按五个入口收敛：

| 入口 | 读 | 写 |
|---|---|---|
| 分析 | 1 个大接口，六视图共用一次请求 | **记一笔（新）** · 发起实验 · 拉相似素材 |
| 复盘 | 1 个接口，一次拿全三段 | 建复盘 · 存成经验 |
| 经验 | 检索 | 确认 · 驳回 · 修订 |
| 素材 | 两栏概览 · 单素材 | 导入 · 映射 · 提取 · **相似检索（新）** |
| 设置 | 四组 | **阈值写入（新）** |

**两页各自一次请求拿全。** 分析页六视图共用一次（沿用现有做法），保证「趋势里看到的」和「疲劳里算的」不是两个时刻的快照；复盘页一次拿全三段，保证①的口径标注和②的每条发现对得上。

**「记一笔」是分析页唯一的写操作。** 它写的是一条发现，不改任何对象的状态——这是 §2 模块一那条铁律在接口层的落法：分析页没有别的写接口可用。

# 第五部分 · 实施顺序

| 期 | 内容 | 为什么这个顺序 |
|---|---|---|
| **1** | 三档结论统一 + 名词表 + `shared/` 组件 + **变量分三类、归因准入规则** | 全模块的语言，先定下来后面才不打架。归因准入规则塞在这期，是给第 7 期留钉子 |
| **2a** | 分析页六视图（视图不重排，只改表达：三档标记 + 名词 + 「怎么算的」）+ 「记一笔」 | 主线上半段。六视图基本原样迁移，所以这半期比看起来轻 |
| **2b** | 复盘页三段（收「记一笔」+ 系统补的发现 + 提交为待确认经验） | 主线下半段。必须紧跟 2a，否则记的笔没地方去 |
| **3** | 素材页：**接通素材库** + 两来源分开 + 千川 + 平台内不走模型 + **建空的时间轴表** | 分析和复盘的输入，不干净上游就没意义。接通素材库排在这一期的最前面——不接通，两来源分不开、平台内的制作参数也带不过来 |
| **4** | 相似素材（按变量重合度） | 解开样本不足这个死结 |
| **5** | 经验页合并 | 闭环的另一半 |
| **6** | 设置页三合一 + 阈值可写 | 低频，最后 |
| **7+** | 视频处理 + 时间轴填充 + 叙事拆解 + 单素材拆解页 | 新基建，整体后置。1、3 期留了钉子，到时是接上去不是改回来 |
| 随时 | 疲劳日均修正 + 导入 21 天演示数据 | 独立，随时插 |

**这份文档是设计，不是实施计划。** 不会写成一份大计划——每期单独出一份，做完一期验收一期再开下一期。第 1 期是全模块的语言（三档、名词、变量分类、归因准入），它定得对不对决定后面几期顺不顺，所以第 1 期的计划要单独细写。

2a 和 2b 拆成两半是为了能分开验收，但**中间不停**：2a 交付时「记一笔」记下的发现暂时只能在分析页自己看到，那是个半成品状态，不适合拿去用。

## 6.4 爬虫：一个没人认领的洞

**素材洞察自己的 PRD 没有爬虫需求。** AM-001~020 二十条里一条都没有。AM-001 说的「外部引用」是**存一个 URL/标识**，不是把内容抓回来。

**但别的系统的文档把它指给了洞察：**

| 出处 | 原话 |
|---|---|
| `24-strategy-contract:143` | 「Strategy 只引用 Insights 的版本化产物，**不直接拥有爬虫和平台数据管道**」 |
| `24-strategy-contract:541` | 「抓取、清洗、存储和来源治理**应由 Insights 或独立 Research Connector 承担**」 |
| `research 补充:13` | 「来源包括**素材洞察的投前爬虫数据**」 |

**代码里是个有意留的空壳**：`internal/integrations/crawler/` 只有一份 README，声明「爬虫和第三方数据是独立集成，不属于素材模块；第三方内容必须经过明确授权导入才能变成素材记录」。洞察后端确认没有任何对外抓取。

**这解释了「行业与受众证据」为什么永远是空的。** `03:21` 提到它，但全份 PRD 只出现这一次，20 条需求无一对应——因为它的数据源就是爬虫，而爬虫在别的文档里被挪到了洞察名下，从来没进 `03` 的需求表。

**本设计的处理：不做，但登记。** 理由是合规成本已经被别的文档写死，是独立模块的量级，和 AM-016 同一档：

- 合规：robots 协议、站点条款、频率限制、版权边界（`24 §7.3`）
- 每条外部证据要留：原始 URL、发布者、观察时间与获取时间、内容哈希、使用权与到期、引用片段 locator（`24 §7.2`）
- 安全：SSRF、下载、隐私、内容安全（`strategy-creative 对抗性评审:85`）

**真要做的时候，入口是素材页的第 ③ 条来源**（见模块四第三条边界），落点是**外部素材证据区**——和平台外素材同一套约束：不进素材库、只读、有保留期、记用途声明。爬来的东西权利状况只会比千川导出的更差，没有理由给它更松的待遇。
